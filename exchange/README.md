# Exchange protocol v1

Этот каталог — асинхронная доска обмена между владельцем, Venya Core и агентами.
Git даёт историю, review и понятный человеку журнал. Он не заменяет live-очередь
SQLite и не используется для секундной координации процессов.

## Каталоги

```text
exchange/
├── inbox/       # новые задания
├── reports/     # результаты и статусы агентов
├── decisions/   # принятые человеком/архитектором решения
└── archive/     # завершённые задания после слияния
```

В пустых каталогах лежит `.gitkeep`.

## Идентификатор

Формат:

`YYYYMMDDTHHMMSSZ-short-slug`

Пример:

`20260618T051500Z-enable-local-fallback`

Одинаковый `id` используется в task, report и decision.

## Поток

1. Владелец или Core добавляет `exchange/inbox/<id>.json`.
2. Агент создаёт ветку `agent/<agent-name>/<id>`.
3. Агент проверяет, что задача не просрочена и соответствует его полномочиям.
4. Результат записывается в `exchange/reports/<id>.<agent-name>.json`.
5. Изменения проходят review владельца или назначенного архитектора.
6. Принятое решение фиксируется в `exchange/decisions/<id>.json`.
7. После merge task и reports переносятся в `archive/<id>/`.

## Правила конкуренции

- Один task-файл неизменяем после принятия агентом.
- Уточнения создаются как новый task с `parent_id`.
- Агент не перезаписывает отчёт другого агента.
- Повторная попытка использует новый report с полем `attempt`.
- Решение считается действующим только после merge в защищённую ветку.

## Безопасность

Запрещено коммитить:

- API-ключи, токены, cookies и приватные ключи;
- полные дампы чатов и персональные данные без необходимости;
- содержимое SecretRefs;
- произвольные tool outputs с секретами;
- команды на необратимые внешние действия без `approval_required=true`.

Секреты передаются по ссылочному имени, например:

```json
{"secret_ref": "MINIMAX_API_KEY"}
```

## Схемы

- Task: `../schemas/task.schema.json`
- Report: `../schemas/report.schema.json`

Перед commit JSON проверяется валидатором JSON Schema.
