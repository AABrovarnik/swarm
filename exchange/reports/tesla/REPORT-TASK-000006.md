## Краткое содержание статьи

Лонгрид агентства Animar Media (автор — Дмитрий Алентьев, опубликован 30.05.2026, ~20 минут чтения, ~26 400 знаков) — коммерческий how-to «как собрать сценарий чат-бота для бизнеса». Структура: быстрый ответ → таблица типов сценариев (продажи, поддержка, заявки, FAQ, бронирование и другие) → 12-блочный шаблон сценария → примеры диалогов → мини-кейс AnimarGPT bot → советы → список ошибок → FAQ. Жанр — маркетинговый: готовые «карты диалога», таблицы «когда шаблон не работает», чек-листы и KPI. Технически нового почти ничего; ценность — методическая: готовая разметка сценария по 12 блокам, типовые ветки эскалации и антипаттерны, которые напрямую ложатся на роли Вени, Студента, Тесли и Изи.

## Переносимые идеи (4–6)

- **12-блочная карта сценария** (приветствие → квалификация → основной поток → возражение → эскалация → закрытие → пост-фоллоу). Пригодна как шаблон `bot-dialog-map.md` для `venya-command-bot` и `student-bot`.
- **Правило эскалации «оператор / не нашёл / дорого / оплата»** — четыре явных триггера, по которым бот обязан передать диалог человеку. Снимает дилемму «когда молчать, а когда звать» в Вене.
- **Таблица «готовый шаблон не работает»** — формализованный список причин отказа (узкая ниша, длинный цикл сделки, чувствительные данные, голос). Полезен как фильтр «наш кейс подходит под шаблон — да/нет».
- **Минимум KPI для сценария:** время первого ответа, % распознанных интентов, % эскалаций, CSAT пост-диалога, глубина сценария. Совпадает с тем, что мы уже обсуждали для Вени.
- **Анти-паттерны «одна длинная ветка» и «кнопки вместо текста»** — годятся как пункты в чек-лист приёмки ботов.
- **Структура FAQ как отдельного слоя**, поверх сценария, а не внутри ветки.

## Замечания (3–5)

- **Коммерческий источник.** Animar Media продаёт те же сценарии, которые рекламирует; цифры бюджетов (3 000–15 000 ₽) и KPI — маркетинговые, не бенчмарк. Использовать только как иллюстрацию диапазона.
- **Упор на проприетарные CRM и конструкторы.** Прямого переноса в наш open-source контур нет; полезна только методическая рамка.
- **Один источник.** Для архитектурных решений недостаточно; для методической шпаргалки — допустимо.
- **Нет независимой верификации фактов** про производительность AnimarGPT bot и конверсии — я их не воспроизводил и не цитирую как доказательство.
- **Голосовой ввод** затронут поверхностно: ASR, приватность, лимиты — требуют отдельного решения Изи/Александра, не моя компетенция.

- **P1. `docs/operations/bot-dialog-map.md`** — перенести 12-блочную карту в нашу документацию, разметив блоки под роли Веня/Студент/Изя/Тесля. Низкий риск, без кода.
